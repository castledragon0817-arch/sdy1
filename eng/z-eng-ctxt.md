보카에서, 36번이나 100번 문장을 눌렀을때( 그 외의 문장 전부 포함. 즉 맨 첫 화면에 나오지 않는 하단의 문장들)

몇 번 누르다 보면, 자꾸 맨 첫 화면으로 이동되는 경우가 있어. (모달을 open했을때, 혹은 모달을 닫았을때 전부) 

"절대로" 화면이 첫 화면으로 이동되면 안되고(pc의 경우 스크롤이 맨 최상단으로 강제이동 되는경우) , "무조건" 그 자리에 있어야해. 문장이 수천개가 되기 때문에 1500번째 문장의 모달을 보는데 갑자기 첫 화면으로 이동되버리면 아주 불편해. 사실상 공부가 불가능함. 이 버그 해결해.

## [1-2.] CLAUDE 결과 [26.10.18 - 04:38]=================================================
1. 원인
 - eng/basevoca.html 의 모달 스크립트(openVoca, 닫힘 처리)가 파일 중간(0033번 모달들 바로 뒤)에 있었다.
 - 기존 코드는 스크립트가 실행되는 순간 이미 존재하던 dialog 에만 "닫을 때 스크롤 복원" 이벤트를 붙였다(document.querySelectorAll('dialog').forEach). 그래서 스크립트 앞의 모달 64개만 복원이 됐고, 0034번 이후로 뒤에 추가된 모달 1274개에는 닫힘 처리가 전혀 붙어 있지 않았다.
 - 모달을 열 때는 화면 고정(body position:fixed, top:-스크롤위치)을 거는데, 복원이 안 되니 고정 상태가 그대로 남는다. 그 상태에서 다른 문장을 누르면 window.scrollY 가 0 으로 읽혀서(고정된 body 라서) top 이 0 으로 저장되고, 결국 맨 첫 화면으로 튀었다. "몇 번 누르다 보면 가끔" 생기는 증상이 이것이다.
 - 36번, 100번처럼 맨 첫 화면에 안 나오는 문장(0034번 이후)만 문제였던 것도 같은 이유다. 이 현상은 insert_batch.py 가 새 모달을 </body> 앞(스크립트 뒤)에 계속 붙이는 구조라서 단어를 추가할수록 심해지는 구조였다.

2. 해결
 - 모달 스크립트를 이벤트 위임 방식으로 교체했다. 닫힘(close, capture 단계)과 배경 클릭을 개별 dialog 가 아니라 document 한 곳에서 받는다. 스크립트 위치와 상관없이, 모달이 몇 천 개가 되어도 전부 같은 방식으로 동작한다.
 - openVoca 에 이미 body 가 고정된 상태(position:fixed)면 저장해 둔 스크롤 위치(vocaScrollY)를 덮어쓰지 않는 보호를 넣었다. 이미 열린 dialog 는 다시 열지 않는다.
 - 닫힘 처리에서 열려 있는 다른 dialog 가 하나도 없을 때만 고정을 풀고 저장해 둔 위치로 scrollTo 한다.
 - 수정 파일: eng/basevoca.html (스크립트 블록 1개만 교체. 모달/카드 내용은 변경 없음)

3. 의도
 - 어디를 누르든, 몇 번 열고 닫든, X 버튼 · 배경 클릭 · Esc 어느 방식으로 닫든 보던 자리에서 절대 이동하지 않게 한다. 문장이 수천 개가 되어도 같은 방식이 유지되게 한다.

4. tradeoff
 - 클릭/close 이벤트를 document 한 곳에서 받으므로 페이지 아무 곳이나 클릭해도 핸들러가 한 번 돈다. 하는 일이 tagName 비교 한 줄이라 비용은 사실상 없다.
 - 기존의 body 고정 방식은 그대로 유지했다. 열고 닫을 때 레이아웃이 한 번 재계산된다.

5. 결과
 - 스크립트 문법 검사 통과(node --check). 해당 스크립트는 파일에 1개뿐이다.
 - 브라우저에서 직접 눌러본 검증은 하지 않았다. 사용자가 아래쪽 문장을 연속으로 열고 닫으며 X 버튼 / 배경 클릭 / Esc 로 확인 필요.
 - commit/push 는 하지 않았다.
